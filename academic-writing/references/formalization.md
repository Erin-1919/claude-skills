# Formalizing Concepts

Companion to [../SKILL.md](../SKILL.md). Read when writing Methods, or when defining any metric, operation, or structural property elsewhere.

The target venues (IJGIS, International Journal of Digital Earth, ACM SIGSPATIAL) reward formal definition. A method described only in prose reads as under-specified there, while the same method expressed as sets, functions, relations, and equations reads as precise and reproducible. The default is therefore: **if a concept can be formalized, formalize it.**

- **Formalize the objects before the operations.** Introduce the data model first (the grid, the cell set, the index space, the attribute mapping) with explicit symbols, then define the operations over it. A reader who has the objects can follow anything built on them.
- **What to formalize.** The spatial data model and its index or address space, each operation or transformation the method performs, every evaluation metric, the algorithm as numbered pseudocode with typed inputs and outputs, and any structural property the argument relies on (containment, transitivity, congruence, conservation of a summed quantity).
- **Give each formal object a short prose sentence, then the display, then the symbol definitions.** State in one sentence what the object is and why it is needed, introduce it with a sentence ending in a colon, display the numbered equation or definition, and follow with a "where" paragraph defining every symbol including index ranges and domains. Never make the reader infer the equation from prose, and never leave a displayed equation unexplained.
- **State load-bearing properties as numbered propositions.** Use "Definition 1", "Property 1", or "Proposition 1", write the property formally (for example, if $a \subseteq b$ and $b \subseteq c$ then $a \subseteq c$), and refer back to it by number where the method or the discussion uses it. A property stated once and cited later is worth more than the same claim repeated in prose.
- **One symbol per concept for the whole paper.** Fix notation at first use and keep it fixed across sections. Follow the usual conventions: italic lower case for scalars and variables, upper case for sets, bold or calligraphic for structured collections if the paper needs a third level, consistent index letters, and a notation table when the symbol count passes roughly ten.
- **Do not formalize the trivial.** An equation that restates a sentence and is never referred to again adds length and invites scrutiny. A formal object earns its place when later text uses it, in an algorithm, a property claim, a metric definition, or a results table. If nothing downstream refers to it, keep the prose.
- **Formalization does not replace interpretation.** After the formal machinery, say plainly what it means for the reader. The equation carries the precision and the sentence after it carries the meaning.
